# @iofbim/ids-checker

Checks IFC models against [buildingSMART IDS](https://github.com/buildingSMART/IDS) files in the
browser — no server, nothing uploaded. Shared by **IofBIM IFC Graph** and the **IofBIM IDS
authoring tool**, consumed in both as a git submodule (TypeScript source, compiled by the app).

## How it works

1. **Parse** — `web-ifc` (WASM) reads the STEP file in a Web Worker; `parser/extractor.ts` turns it
   into entities (attributes, property sets, classifications, materials) and relationship triples.
2. **Load** — `db/ingest.ts` bulk-loads them into DuckDB-WASM tables (`db/schema.ts`) via Arrow.
3. **Check** — `ids/parse-ids.ts` reads IDS 1.0 XML; `ids/facet-sql.ts` + `ids/evaluate-ids.ts`
   turn every specification into SQL: applicability facets select the entities in scope,
   requirement facets become pass/fail columns (all six facet types, cardinality, value
   restrictions with SI-normalised numeric bounds), plus specification-level cardinality.
4. **Report** — `ids/ids-report.ts` builds CSV or standalone HTML failure reports.

The engine is an in-house implementation, not the buildingSMART reference (`ifctester`); results
can differ on edge cases.

## Use

```ts
import { configureChecker, loadIfcModel, checkIds, unloadIfcModel, reportToCsv } from "@iofbim/ids-checker";

configureChecker({ duckdbBaseUrl: "/checker/duckdb", webIfcWasmPath: "/checker/" });
const model = await loadIfcModel(file, { onProgress: (p) => console.log(p) });
const { document, results } = await checkIds(idsXml, [model.modelId]);
const csv = reportToCsv(document, results);
await unloadIfcModel(model.modelId);
```

Apps with their own pipeline import the modules directly: `@iofbim/ids-checker/parser/*`,
`/db/*`, `/ids/*`.

### Binary assets

The app serves DuckDB's wasm + worker and `web-ifc.wasm` itself. Copy them from `node_modules`:

```bash
ids-checker-copy-assets public/checker   # e.g. as "predev" / "prebuild"
```

…and point `configureChecker` at that folder. The worker that parses IFC is created with
`new Worker(new URL("./parser/parser.worker.ts", import.meta.url), { type: "module" })`, which
Vite and webpack 5 bundle from the package source.

### Consuming the TypeScript source

- **Vite**: works as is (keep `@duckdb/duckdb-wasm` out of `optimizeDeps`).
- **Next.js (webpack)**: add the package to `transpilePackages`, and map `.js` import
  specifiers to `.ts` (`config.resolve.extensionAlias = { ".js": [".ts", ".js"] }`).

## Develop

```bash
npm install
npm test          # vitest
npm run typecheck
```

`src/parser/ifc-attr-names.generated.ts` is generated by `scripts/gen-ifc-attr-names.mjs` from an
IFC schema dump that is not in the repo (`IFC_ATTR_SOURCE=<path> node scripts/gen-ifc-attr-names.mjs`).

Changes here are a separate commit in this repo; each app then bumps its submodule pointer.
